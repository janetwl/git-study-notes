# 方法卡 · 程序错误六检查(证据处理流水线的毛病)

**何时使用**:用户的立场不算歪,但**处理证据的过程**有毛病:只看顺风向材料、对己对人两套标准、第一判断从不复查、一句话概括一群人、把复杂事压成单因、"之后发生故因此发生"。

**原理**(第十章,六个程序错误):
1. 有偏见的证据考量——两种形式:只寻求肯定你偏见的证据;逆风证据来了仍选顺风。
2. 双重标准——同一行为换阵营就换标签("有想象力"vs"乌托邦")。
3. 草率的结论——"没有充分证据就作出的判断";学术大案:一战200万新兵智力测验→"痴愚者"结论→推动1924移民法。
4. 过度概括与刻板成见——刻板成见是"特别抵制变化的过度概括";限定语规则:不加"一些/大多数"即等于说"所有"。
5. 过度简单化——把一面当唯一面(学生没学好必是老师错);情感与媒体耸人听闻机制火上浇油。
6. 事后归因——先发生≠因为发生(萨姆迟到得D案;迷信的心理基础)。

**用法步骤**:
1. 检索方向检查:让对方先讲**相反观点的最佳论证**,再讲支持的(解毒程序原文:先读相反观点再读支持观点)——讲不出反方论证即偏食。
2. 标准一致性:把评价换成己方/对方两个版本,事先写下标准并一致执行,即使数据不支持己见。
3. 草率三步解毒:先穷举所有可能的结论→检查每条的证据→允许推迟判断且不丢脸。
4. 量词体检:断言里有没有"一些/大多数/常常"?没有,就按"所有"来质疑;经验越有限,断言越谨慎。
5. 补写另一面:给一切一面倒的断言写"另一半故事"(餐厅老板、悬挂滑翔协会案例为模板)。
6. 因果闸:"暂缓作出因果关系的判断，直到你排除了其他的解释，包括巧合。"

**边界**:
- 追问因果关系本身没错,错在跳过排除程序直接认定。
- 提及可观测的群体统计模式≠刻板成见(索维尔界线);差别在于是否抵制反例、是否代替个体证据。
- 合法简单化存在(交流需要简化);歪曲的是"把简化当完备"。
- 程序错误与立场错误互为表里(ch9的14条假定即本章错误的伏笔),诊断时两头都查。

**出处**:第二篇·第十章《程序错误》(notes/ch10)
