# 核心概念(01)

## 1. 基本命题:雇佣,而非购买

用户不是在"购买"产品,而是**雇佣**一个产品/服务,帮自己在特定情境下完成任务(hire a product to do a job)。【B:三书共同出发点】

经典类比:没人想要一台电钻,人们要的是墙上的洞——再深一层,是"挂上全家福后家里温馨的感觉"。JTBD 就是教你一层层问到"他到底想把什么事办成"。【C:编者通俗化转述】

## 2. 任务(Job)

- 定义:用户在**特定情境**下想取得的**进步**,与产品无关。【B:《与运气竞争》第2章"追求进步,而非产品"】
- 细分单位:不是"人群"(25-35岁女性),而是"任务+情境"。情境变了,同一人群的购买逻辑完全变(奶昔的早晨 vs 下午)。【B:《与运气竞争》+ Ulwick"市场的统计学定义"】
- 三层结构:
  - **功能任务**:把事情办成(把地拖干净)
  - **情感任务:自己感觉如何**(觉得自己是会持家的/不掉价)
  - **社会任务**:别人怎么看我(在家人面前体面)
  【B:三书均有,《待办任务》第2章列为构成元素】
  实践含义:只满足功能任务的产品,会被三层都满足的对手"解雇"。【C】
- 层级/范围/种类:任务有上位任务(核心任务)和下位任务(关联任务)层级。【B:《待办任务》第2章"层级/范围/种类",细节以原书为准——本库未展开】

## 3. 任务陈述写法

公式:**动词 + 对象 + 情境澄清语**,不带解决方案、不带产品品类。【B:Ulwick 理论篇"任务陈述"】

- 好:"在通勤路上让自己不那么无聊" / "在有限时间内让一家人吃上像样的饭"
- 坏:"买一杯奶昔"(混入了解决方案)/ "提升用户体验"(太空,没有对象和情境)
详见过 `methods/job-statement.md`。

## 4. 雇佣与解雇,以及"真正的竞争对手"

- 用户"雇佣"一个方案,不满意就"解雇"换下一个。【B】
- 推论(锋利处):竞争对手不是同类产品,而是用户在当时情境下**能想到的所有替代**——奶昔的对手是香蕉、贝果、无聊;视频网站的对手是刷手机甚至发呆。【B:《与运气竞争》奶昔案例引申;Netflix 案例】
- 自检:你的产品在被哪些"不像竞品的东西"解雇?没人"雇佣"你的空档时段去哪了?【C】

## 5. 期望成果(Outcome)的雏形概念

用户判断"这事办得好不好"有一套自己的标准,即期望成果;重要性高 + 现有方案满足度低的成果 = 创新机会。量化写法见 `03-odi-outcomes.md`。【B:两派共同】
