# ODI:任务地图、期望成果、机会算法(03)

Ulwick 成果导向创新(ODI)——把 JTBD 从直觉变成可重复流程。【B:《Jobs to Be Done: Theory to Practice》理论篇/方法篇】

## 1. 任务地图(Job Map)

任务是最小分析单位;任何任务都可拆成一条**与产品无关的执行阶段**序列。【B:Ulwick 理论篇"任务是最小分析单位"】

通用执行阶段(抽象层,每类任务都适用):
**定义 → 查找 → 准备 → 确认 → 执行 → 监控**(并处理异常/跟进结果)。【B:Ulwick 理论篇"任务地图";《待办任务》第3章"制作任务地图"】

用法:把用户的任务沿阶段拆开,后续所有"期望成果"都挂在某个阶段上,不悬空。具体步骤见 `methods/job-map.md`。

## 2. 期望成果陈述(Outcome Statement)

公式:**"在(某执行步骤)时,尽量减少(某个不想要的结果)的概率/发生率"**,不带产品、不带方案。【B:Ulwick 方法篇;示例"备份照片时,尽量减少备份中断的概率"】

好例:"给孩子选 3D 打印课时,尽量减少课程中途孩子失去兴趣的概率"
坏例:"希望 App 界面更美观"(混入方案,且没挂到步骤)

## 3. 机会算法(Opportunity Algorithm)

对每条成果,让用户打分:重要性 I、现有方案满足度 S(各 1~10)。【B:Ulwick 方法篇】

> **机会分 = I + max(I − S, 0)**

- I 高、S 低 → 机会分爆表 = **欠满足成果** → 创新机会所在
- I 高、S 也高 → 过满足 → 别再堆功能,考虑简化或降价交付
- I 低 → 无论 S 如何都别投入
【B:公式本身;判读为 C 级展开】

## 4. 市场的统计学定义与细分

- 市场 = **任务 + 情境**,不是产品品类。(不是"咖啡市场",而是"通勤路上扛饿解闷市场")【B:Ulwick 方法篇"市场的统计学定义"】
- 细分方法:按**未满足成果的分布**把人群切成聚类,而不是按人口属性;同一人口属性的人可能雇你做完全不同的任务。【B:Ulwick;《待办任务》第7章"基于期望成果的市场细分"】

## 5. 从成果到应用

- 创意挖掘:从欠满足成果出发系统生成方案;过满足成果出发做减法。【B:Ulwick 应用篇】
- 价值主张与营销文案:用任务语言写"帮谁、在什么情境、把什么任务办得更漂亮"——"10 分钟搞定一桌菜"胜过"800W 大功率"。【B:两派共识】
- 采用率预测:功能独立性模型(产品完成后,任务能否端到端独立办成,决定采用快慢)。【B:Ulwick 应用篇,只在此立目;算法细节本库未展开,勿冒充实操】
