# 访谈方法:发现任务与转换挖掘(04)

核心纪律:**不问"你想要什么功能",沿着一次真实的"雇佣/解雇"经历问。**【B:两派共识;《待办任务》第3-4章】

## 1. 两条访谈路线

- **发现访谈(Job Discovery)**:用户还没形成明确转换,目标是挖出任务本身和任务地图。【B:《待办任务》第3章"发现任务、制作任务地图"】
  打法:请对方完整叙述"上一次办成这件事"的全过程(哪怕很笨拙:用 Excel 手搓、问朋友),你沿时间线追问每一步在躲开什么不想要的结果。
- **转换访谈(Switch Interview)**:用户刚换过方案,目标是挖四力。【B:《待办任务》第4章"转换访谈挖掘、四力模型分析";《与运气竞争》第4-5章同源】
  打法:一次成功的转换访谈 = 让对方讲一个"从起念到后悔/庆幸"的故事。脚本见 `methods/switch-interview.md`。

两派立场:发现派(Christensen/Moesta)靠叙事挖任务,度量派(Ulwick)靠成果清单量化排序;《待办任务》第4章对两种方法有明确立场比较。【B,立场细节本库未展开——用户若要较真,读原书第4章】

## 2. 时间线挖掘七问(转换访谈的骨架)

【C:由蒸馏内容整理成的可执行提问串,与《与运气竞争》第5章"听见顾客没说出口的话"同向】

1. 你第一次觉得不对劲是什么时候?当时发生了什么具体的事?(触发时刻)
2. 在那之前你用什么凑合?为什么当时没换?(惯性)
3. 起念之后,你考虑过哪些替代方案?(真竞争对手清单)
4. 是什么吸引你差点/最终选定现在这个?(推力②)
5. 做决定时你害怕什么?谁反对过?(焦虑)
6. 最后是什么"最后一根稻草"让你真掏钱了?(临界点)
7. 现在回头看,哪里还不如旧方案?(解雇线索 + 新的欠满足成果)

## 3. 访谈纪律

- 问"上一次",不问"如果"——假设性问题产出的全是幻觉数据。【C,两派共识】
- 一次访谈至少挖到:1 个触发时刻、1 个替代方案清单、4 股力各自的原始说法。【C】
- 样本逻辑:JTBD 访谈求**情境饱和**(新访谈不再出现新任务/新成果)而非统计样本量。【C,与《待办任务》第3章访谈须知同向】
- 访后动作:把原始叙述转成①任务陈述②任务地图③成果清单,再进 03 的打分。【B:最小实操三步】
