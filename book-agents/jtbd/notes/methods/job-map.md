# 方法卡:任务地图

**何时用**:任务陈述写好后、找期望成果之前。把任务拆成阶段,成果才有挂钩点。

## 通用执行阶段(Ulwick 抽象层)

**定义 → 查找 → 准备 → 确认 → 执行 → 监控(+处理异常)**

## 五步操作

1. 写下已合格的任务陈述(用 `job-statement.md` 质检)。
2. 请用户(或你自己代入)**完整走一遍"上一次办成这件事"**的过程,哪怕是笨办法(手抄、问朋友、Excel 硬搓)。
3. 把过程中的动作归进六个阶段;归不进去的阶段说明任务陈述定错了层,重做第 1 步。
4. 每个阶段追问:"这一步你在躲开什么不想要的结果?"——每条回答都是一颗期望成果的种子(交给 `outcome-statement.md` 加工)。
5. 产出:一张"阶段 × 该阶段动作"表 + 每阶段下的原始痛点语录。

## 产出模板

| 阶段 | 用户实际做什么 | 在躲开的不想要的结果 |
|---|---|---|
| 定义 | (例)纠结周末到底给娃安排什么 | 怕选了个娃十分钟就腻的活动 |
| 查找 | …… | …… |

| 监控/异常 | | |

## 边界提醒

- 任务地图是**过程**分解,不是用户旅程图(后者含情绪曲线与触点,是《待办任务》第10章"消费旅程图"的事)。混用会导致成果挂错位置。【B/C 混合:概念区分为编者整理】
