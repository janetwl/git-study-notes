# ch51 · 关于"提问"的智慧(20170721)
出处:专栏第 51 篇《51.20170721关于"提问"的智慧★》。关键词:提问、原则、策略、(原栏如此,行末顿号为原文)

## 定位
第一季收官前两周,承接 ch50 的"提问三要求",把"提问"升级为一种可训练的核心能力:提出高质量问题的过程,就是我们解决问题的过程——提问因此是学习能力(ch44)与自学能力的现场检验。本篇同时是"毕业前的一季":文末发布结集新书《财富自由之路》,给第一季画上仪式句号。

## 核心论点(方法论优先)
- 学霸真正牛的地方不是回答问题的能力,而是提出好问题的能力;他们很少提问,多数时间一个人查词典、翻材料、自顾自折腾,一旦提问质量一定相当高。
- 好问题的三个要素(判断标准):1. 无法通过简单搜索得到答案(查单词意思、地区人口这类问题,能问出口的一定是怕麻烦的懒人——成为学霸第一步是不怕麻烦);2. 有充足的背景信息支撑(做足功课会把问题定义得非常清楚:什么情境、涉及什么概念、尝试过什么解法;不限定范围的问题如"去大城市还是小城市工作"只能得到"看情况");3. 不会是纯粹的索取——姿态接近"讨论"而非"索取",最直接的体现是用选择题方式提问,或开放式问题里也加入自己的思考选项,原文示例:"我对xxx有些疑问，现在想出了两种解决方法，一是xxx，二是xxx，老师觉得哪个方法可行？老师还有没有其他更好的方法？"。
- 没有多少人讨厌被问题问,大家只讨厌被蠢问题问,因为显得提问者毫无诚意;连自己都不重视的事,不能要求别人重视。
- 拒绝伸手党是有原则:坚持原则并非冷血,而是对大家都有利的一种策略(读者室友案例:拒绝让提问者知道要远离伸手党、也不埋怨不近人情,关系反而可能更好;一直隐瞒不满,某天爆发就是关系破裂)。
- 提出高质量问题者起码可判定:有非常强大的自学能力;能提好问题的人到哪里都不会做得太差。
- 老师/高手的真身:老师其实也只不过是自学能力强的学生;英语老师多出的技能不过是遇到问题知道如何查词典、查语法书、参考不同词典和语法书;高级程序员只比低级程序员多会检索文档、会问 Google。做完功课基本 90% 的问题已被解决;剩下的问题确实不错,就去找能回答的人,好问题他们会很愿意回答(帮助自己提高)。
- 本篇真正送出的是另一把钥匙:如何自己找出大多数问题的答案。为提出一个值得回答的问题要付出很多努力、查很多资料,等准备充分时原来的问题可能已经被解决了——能力正是在这个过程中提升的。挡住绝大多数人的是"怕麻烦"三个字;不践行就不知道会遇到怎样的麻烦,为了合理化放弃会臆测出很多根本不存在的问题(人总有合理化自己行为的倾向,呼应 ch45)。对策:把着眼点放到眼前,先把能做的事情搞定,再一步步向外延展。
- 面试操作法:你问他们什么其实没那么重要,他们问你什么才更加重要。把面试者放在提问位置,没有对行业的仔细思考、没对应聘工作做调研,基本问不出有质量的问题——像幽默感无法伪装,提问质量无法伪装;由此马上区分有思考能力/自学能力的人与装样子的人。
- 提问是很少被列出来却非常重要的识人标准(比高考分数、招聘条件等显性标准更难达到的,是那些看不见的"标准");反面例子:打电话挂了又反复回拨问细节、接二连三发生,会被归入"不靠谱"分组,以后有重要事情一定不拜托他。
- 与牛人建立联系的操作:与其只加微信翻朋友圈,不如想几个好问题在恰当时机提出,更可能留下印象、为以后交流奠定基础;哪怕没成功,你也得到了一个好问题的答案,这本身已经非常有价值。
- 推荐教程:Eric Steven Raymond《How To Ask Questions The Smart Way》(2001 年首发,已至 3.10 版),地址 http://www.catb.org/esr/faqs/smart-questions.html ;虽写给程序员但适用性不限;程序员世界最容易检验提问质量(技术问题通常有具体解法,前提是你花过时间思考),烂问题会被撅回去:"RTFM""STFW"——不知道意思就去教程里看,这也算一种实践。
- 作者认为最重要的三条原则:
  一、只要是搜索引擎能回答的就别问别人。时代变了:问人之前不先问问搜索引擎是可耻的;一个点点鼠标就能找到答案的问题,很难期待有人主动花时间回答;人们最宝贵的资源是注意力,让别人替你完成基础搜索是不尊重他人注意力。事实:"相信我,你并不孤独"——大部分技术性、事实性问题世界上早就有解决方案(只有你一人碰到的几率非常小)。观点类问题搜索也能帮补背景资料、界定提问范围;具体搜索技巧见公众号回复"搜索"。简单粗暴公式:Google + Wikipedia + English = Almost Everything。等式左边都只是工具(连英语也是交流工具),工具只有到了以"伸手党"为耻的人手里才发挥巨大作用,对伸手党则放大懒惰(有人把作业丢网上直接要解答步骤和答案,没得到还埋怨网友能力太差);你利用工具的"姿势",会反过来决定你未来的走向。
  二、你要知道自己提问的目的是什么。语言会限制思维:"这句话(应该)怎么翻译啊?"这个问法给英语学习者造成严重却看不见的障碍——翻译只是外语众多用处之一,问法却把"之一"变成全部,本末倒置;且翻译起码分直译和意译,多数情况下这样提问的人没意识到自己实际问的是"怎么直译",而很多看似简单的句子很难甚至没办法直译,答案很可能"我也不知道……"。对英语学习者(将来的英语使用者)来说,更为重要的是"理解",而非"翻译";就算需要翻译,往往也更多需要意译。正确问法:"这句话应该怎么理解呢?"或"这句话到底是什么意思?"——自己清楚发问目的,对方才知道怎么答让你弄明白,这才是有效沟通。仅仅是目标定义不精确,就让一个原本可能被回答的问题变成无解的问题。
  三、要方便他人回答。问题即便简短也要完整:"《动物农庄》和《围城》哪本书更好？"不如"我要去海南度假一周，每天会有两个小时的阅读时间，希望找本书读一读，不知道《动物农庄》和《围城》应该选哪一本？或者有什么其他书可以推荐吗？";完整不需要长篇累牍,言简意赅把主要信息说出来即可。别把设问当提问(设问=不需要对方回答的问题):演讲者把本该自己回答的问题甩给听众再停顿等待,就是愚蠢、现场一定"冷";也别问"三岁小孩都能回答"的问题,听众会觉得被侮辱智商。相对稳妥的办法:尽量问对方选择题——你提供的选项让对方觉得你花时间研究了解决方法,回答也更有针对性;怕选项不够好,可再加一个开放式选项。
- 兜底操作:自己折腾半天也没搞定、提问后也没得到解答(所有人都不是全知全能的),就把问题记在本子里;大量过去积攒的问题,都会在某一天自动出现解决方法——前提是你还记得那个问题;如果不记得,估计它也从你的生活里消失了。
- 分寸:主题是"如何提问"而不是"如何不提问";理论上可自学绝大多数知识,但需要老师就是为了缩短过程、让成长更快。你要在现有水平上做好功课,才可以去向别人发问——不能要求小学生提出大学生水平的问题,初学者也不能对自己提不切实际的要求,分寸自己拿捏。检验标准:问心无愧——提出问题时内心坦荡真诚,已在自己能力范围内做了足够功课,不是抱着伸手党心态请教;有自知之明的人秉持这态度,问题一定不会太差。

## 辅导提示
- 用户提问总得不到回答/被敷衍 → 用三要素自查:能搜到吗、背景信息够吗、是否纯索取;改造成带选项的"讨论式"提问。
- 用户英语读不懂就问"怎么翻译" → 用目的论:把"怎么翻译"换成"应该怎么理解/什么意思";问直译往往无解。
- 用户想请教牛人却只加了微信 → 想几个好问题在恰当时机提出;没成功也得到一个问题的答案。
- 用户是管理者/面试官 → 让候选人提问,当场区分自学与思考能力;幽默感和提问质量都无法伪装。
- 用户不会拒绝伸手党或怕得罪人 → 坚持原则并非冷血;隐瞒不满到爆发才是关系破裂之时。
- 用户问题当下无解 → 记到本子里,大量积攒的问题会在某一天自动出现解法;前提是记得它。
