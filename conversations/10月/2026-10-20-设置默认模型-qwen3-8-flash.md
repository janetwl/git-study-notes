# 对话记录:设置 Claude Code 默认模型为 qwen3.8-flash

- **日期**:2026-10-20
- **工作目录**:E:\git-workspace
- **主题**:把新会话的默认模型固定为 `qwen3.8-flash`,并排除 `ANTHROPIC_MODEL=auto` 环境变量的干扰

---

## 1. 用户请求

用户先执行了 `/model` 命令,输出:

> Set model to `qwen3.8-flash` and saved as your default for new sessions
> ANTHROPIC_MODEL is set to `auto` — new sessions use that while it is set

随后用户说:

> 以后打开默认选择qwen3.8-flash这个模型吧

## 2. 处理过程

### 2.1 加载 update-config skill

判断这是 harness 配置问题(settings.json),不是记忆偏好问题,于是调用 `/update-config` skill,任务描述:用户想让新会话默认使用 qwen3.8-flash;`/model` 已保存默认,但 `ANTHROPIC_MODEL=auto` 环境变量会优先于保存的默认值,需要检查并调整设置。

### 2.2 读取三个 settings 文件

- `C:\Users\Lenovo\.claude\settings.json`(用户级)——存在,内容:

  ```json
  {
    "env": {
      "ANTHROPIC_AUTH_TOKEN": "sk-sp-...",
      "ANTHROPIC_BASE_URL": "https://token-plan.cn-beijing.maas.aliyuncs.com/apps/anthropic",
      "ANTHROPIC_MODEL": "auto",
      "ANTHROPIC_DEFAULT_HAIKU_MODEL": "qwen3.6-flash",
      "ANTHROPIC_DEFAULT_SONNET_MODEL": "qwen3.8-flash",
      "ANTHROPIC_DEFAULT_OPUS_MODEL": "qwen3.8-max",
      "CLAUDE_CODE_SUBAGENT_MODEL": "auto",
      "CLAUDE_CODE_MAX_CONTEXT_TOKENS": "983616"
    },
    "model": "sonnet"
  }
  ```

- `E:\git-workspace\.claude\settings.json`(项目级)——不存在
- `E:\git-workspace\.claude\settings.local.json`(项目本地)——不存在

**发现**:`env.ANTHROPIC_MODEL = "auto"` 会覆盖保存的默认模型;`model` 字段当时是 `"sonnet"`。

### 2.3 确认 auto 的来源(排除系统环境变量)

- `command -v jq` → jq 不可用;shell 里 `ANTHROPIC_MODEL = auto`
- `reg query HKCU\Environment` / `HKLM\...\Environment` → reg.exe 被权限拦截(乱码报错"注册表编辑…")
- 改用 PowerShell:

  ```powershell
  [Environment]::GetEnvironmentVariable('ANTHROPIC_MODEL','User')    # → 空
  [Environment]::GetEnvironmentVariable('ANTHROPIC_MODEL','Machine') # → 空
  ```

**结论**:`auto` 只来自 settings.json 的 `env` 块(注入到进程),不是 Windows 系统环境变量,改这一个文件即可。

### 2.4 修改 settings.json(两处编辑)

1. **删除** `"ANTHROPIC_MODEL": "auto",` 这一行
2. **`"model": "sonnet"` → `"model": "qwen3.8-flash"`**(让默认值直接写模型本名,不再依赖别名间接映射)

保留未动:`ANTHROPIC_BASE_URL` / `ANTHROPIC_AUTH_TOKEN`(阿里云网关)、`ANTHROPIC_DEFAULT_HAIKU/SONNET/OPUS_MODEL` 三个别名映射、`CLAUDE_CODE_SUBAGENT_MODEL=auto`(子代理仍走 auto)。

### 2.5 验证 JSON

第一次验证命令因 `$_` 被 bash 展开而失败(报 ParserError),换不含特殊字符的写法重试:

```powershell
try { (Get-Content -Raw 'C:\Users\Lenovo\.claude\settings.json' | ConvertFrom-Json | ForEach-Object model) ; 'JSON OK' } catch { 'JSON INVALID' }
```

输出:

```
qwen3.8-flash
JSON OK
```

(settings.json 一旦格式坏会被整体静默忽略,所以这步必须做。)

`C:\Users\Lenovo\.claude\settings.json` 改后:

## 4. 生效逻辑(给用户的总结)

- 新开的会话 → `model: qwen3.8-flash` 直接生效,没有 env 变量抢优先级。
- 以后用 `/model` 换别的模型并保存默认,也能正常生效,不会再被 env 覆盖。
- 当前会话已在 qwen3.8-flash 上运行;重启后走新默认。

## 5. 经验小结

- `ANTHROPIC_MODEL` 环境变量优先级 **高于** settings.json 的 `model` 默认值——`/model` 提示"new sessions use that while it is set"就是这个意思。
- 改环境变量前先分清来源:settings.json `env` 块 vs Windows 用户/机器级环境变量。PowerShell 的 `[Environment]::GetEnvironmentVariable(name, 'User'/'Machine')` 是 reg.exe 被拦时的可靠替代。
- Git Bash 里向 PowerShell 传内联脚本注意 `$_`、`$env:` 等会被 bash 先行展开。
- 每次编辑 settings.json 后都要做 JSON 语法验证。
